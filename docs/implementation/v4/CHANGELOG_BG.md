# Промени във версия 4.0

| Област | v3 | v4 — действащо решение |
|---|---|---|
| VPN при обекта | WireGuard на ROCK Pi | WireGuard на отделния EMS рутер |
| Машинна VPN идентичност | По ROCK Pi | Уникален ключ за рутера/обекта |
| ESP32 до backend | Независим публичен MQTTS | MQTTS през рутерния тунел; без WAN fallback |
| Централен MQTTS вход | Публично TCP 8883 | TCP 8883 само на backend VPN адреса |
| AllowedIPs на Windows | Edge tunnel host | Router tunnel host + CONTROL и TELEMETRY CIDR на обекта |
| Мрежи при обекта | По-ограничена VPN адресация | Уникални CONTROL и TELEMETRY мрежи, отделен недостъпен OT |
| ROCK Pi listener | Възможен bind към wg0 адрес | Bind към CONTROL адрес; няма зависимост от VPN услуга |
| Отказ на рутер/VPN | Различни възможни cloud канали | И Modbus, и cloud MQTTS отпадат; локалната RS485/OT работа остава |
| Ключове | Постоянни машинни ключове | Същата политика, но с enrollment/revoke на site router |
| Сигурност | R01–R20 и T01–T70 | Запазени, адаптирани и допълнени с R21–R30 / T71–T95 |

Запазват се шестте основни услуги, отделната GrideX PostgreSQL, HAProxy,
единният API договор, least-privilege ролите, anti-replay/TTL/lease изискванията,
локалните ограничения, backup/restore, подписаните/проверени обновявания и
приемането преди реално управление.

В пакета няма Nginx, TimescaleDB или втори MQTT broker като нови изисквания.
Ако друг документ/илюстрация ги показва, той не определя тази архитектура.

Това е нова версия на плана, не отчет за извършена имплементация.
