# Мрежова схема за имплементация v4

[Отвори PNG схемата](GrideX_Network_v4.png).

Схемата е общ шаблон за два обекта; останалите се добавят по същия модел
с уникални router keys и несе-припокриващи се CONTROL/TELEMETRY диапазони.
Няма реални IP адреси или VPN ключове в изображението.

Синият и зеленият път показват отделни peer връзки на site routers към
един native Windows WireGuard hub. ROCK Pi и ESP32 са вътрешни устройства,
не VPN участници. MQTTS 8883 е само на hub VPN адреса. Public web 443/80
не е devices fallback и се настройва отделно според runbook.

Всеки site има CONTROL (означен и EMS_EDGE в схемата) и TELEMETRY VLAN.
RS485 е локална връзка и не маршрутизира IP между зоните. Vendor OT е
зад втори NIC на ROCK Pi и не е рекламиран във WireGuard.

Схемата е логическа, не packet capture и не пълна ACL таблица.
Матрицата на firewall и конкретният ред на изпълнение са в runbook файловете.

Този файл е наличната проверена схема от разговора, копирана без промяна.
Няма SVG оригинал в пакета. Не се използват генерираните преди това
илюстрации с Nginx/TimescaleDB, обща device LAN или числови example addresses.
